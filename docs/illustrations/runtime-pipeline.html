The runtime pipeline

Every citizen interaction passes through this 14-step orchestrator pipeline.
The language model runs at step 7. Everything else is deterministic code or platform infrastructure.

Deterministic code
AI (language model)
Platform infrastructure
Deterministic setup
01
Policy evaluation deterministic
Evaluates the service's eligibility rules against citizen data via PolicyEvaluator. Returns eligible/ineligible with reasons.
02
State machine setup deterministic
Creates StateMachine from the service's journey definition. Restores current state from client session. Computes allowed transitions.
03
Field collector deterministic
Seeds FieldCollector from the identity schema and citizen data. Tracks required versus collected fields and identifies what is still missing.
04
Agent selection deterministic
Selects triage mode or journey mode. The choice determines prompt composition and available tools.
05
Strategy context and system prompt deterministic
Assembles the system prompt from layered fragments: personality, persona style, scenario, service descriptions, guardrails, and output format.
06
Build tools deterministic
Calls ServiceStrategy.buildTools(). The deterministic strategy returns an empty array; the tool-based strategy returns service-specific check and advance tools.
Language model
07
Agentic loop ai
Up to 5 iterations: call the language model, dispatch any tool calls via the adapter, accumulate results. This is the only step where the LLM generates content.
Validation and override
08
Parse structured output deterministic
Extracts the JSON block from the LLM response. Parses conversation title, tasks, proposed state transitions, and extracted facts.
09
Build tasks deterministic
Transforms parsed task descriptions into typed TaskEntry objects with structured fields: type, title, description, options, metadata.
10
State transitions deterministic
Validates the LLM's proposed transition against the StateMachine. Rejects illegal transitions. Applies forced and auto transitions.
11
Deterministic task injection deterministic
Overrides LLM-generated tasks with platform-generated cards at specific states. Consent cards, payment forms, and document uploads are always rendered by the platform.
12
Consent requests deterministic
Surfaces consent grant cards at the eligibility-checked state. Required grants must be accepted to proceed; optional grants can be declined.
13
Handoff detection deterministic
Evaluates safeguarding triggers, edge-case conditions, and escalation rules. When triggered, the conversation routes to a human adviser with full context.
14
Version metadata and trace platform
Hashes the system prompt, stamps ruleset and journey versions, builds the full pipeline trace with per-step timing. Written to the evidence store for audit and replay.
The LLM runs at step 7 out of 14. Everything before it is deterministic setup; everything after it is validation and override. The language model proposes; the platform disposes.
